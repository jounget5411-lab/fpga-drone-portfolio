# 실행 환경과 검증 범위

[프로젝트 소개로 돌아가기](../README.md)

## 환경

- 저장소의 보드 설정: Zybo Z7-20 / Zynq-7000, 장치 `xc7z020clg400-1`
- Vivado 블록 설계 기록: 2025.1
- 프로세서 애플리케이션: Cortex-A9 / standalone / C++
- 영상 입력 관련 코드: OV5640 / Pcam 5C, MIPI 수신 IP
- 포함된 하드웨어 자료: Vivado 프로젝트, 블록 설계, RTL, 여러 XSA
- 포함된 소프트웨어 자료: Vitis 컴포넌트 설정, 카메라·VDMA 코드, SNN 가중치 헤더

## 복원할 때 먼저 맞출 항목

1. 실제 사용한 Vivado·Vitis 버전, 보드와 카메라 모델을 확인합니다.
2. 원본 `hw.xpr`의 IP 경로와 참조 RTL을 복원합니다.
3. 사용할 XSA와 플랫폼을 선택하고 BSP 및 `xparameters.h`를 다시 생성합니다.
4. 애플리케이션의 플랫폼 참조, VDMA 주소·인터럽트·메모리 영역을 해당 하드웨어와 맞춥니다.
5. 카메라 출력 → 그레이스케일 저장 → 차분 영상 → 가중치 로드 → 분류 결과 순서로 관찰합니다.

현재 `app_component/vitis-comp.json`의 플랫폼 이름은 `platform_snn_real_final`입니다. 저장소에는 `platform_0515_2`와 `platform_8`이 있어, 복원 시 이름과 하드웨어 매칭을 확인해야 합니다. 플랫폼 설정에는 원래 개발 PC의 절대 경로도 포함되어 있습니다. 이 이유로 단일 명령으로 빌드된다고 안내하지 않습니다.

## 관찰 도구

C++ 코드에는 UART 명령으로 160 × 90 PGM 형식의 원본 영상과 차분 영상을 출력하는 기능이 있습니다.

| 명령 | 코드상 기능 |
|---|---|
| `y` | 그레이스케일 원본 프레임 덤프 |
| `z` | 차분 프레임 덤프 |
| `r` | SNN 결과 한 번 읽기 |
| `s` | SNN 결과 연속 출력; 코드상 리셋으로 종료 |

UART 출력에는 메뉴와 진단 문자열도 있으므로, 저장 파일에서 영상 데이터 경계를 구분해야 합니다.

## 현재 문서가 보여주는 범위

이 포트폴리오는 공개 소스와 프로젝트 수행 기록·개발 요약을 함께 정리한 문서입니다. 수행 기록에는 6월의 단일 보드 통합·시연·계측 결과가 있으며, 소스 설명에 사용한 공개 스냅샷은 그보다 앞선 구현을 담고 있습니다. 이 문서 제작 과정에서 FPGA 보드 실행, RTL 시뮬레이션, 합성·타이밍 검증 또는 모델 정확도 평가를 새로 수행하지 않았습니다.

| 근거 | 이 문서에서 설명하는 내용 | 남은 연결 자료 |
|---|---|---|
| 공개 코드 `206404b` | 영상·VDMA·특징 추출·SNN과 CNN 블록 연결 | 공개 소스와 최종 통합 빌드의 변경 이력 |
| 6월까지의 수행 기록·개발 요약 | 런타임 CNN 가중치 로드, PS 후처리, 팬틸트, 시연·계측 과정 | 최종 RTL·가중치·bitstream·XSA·애플리케이션 묶음 |
| 기록에 수록한 사진·검출 화면·전류 그래프 | 시제품 형태, 단일 프레임 검출 비교, 상태별 전류 | 원시 측정·평가 결과와 반복 조건 |

- 카메라 모드의 60 fps 설정은 전체 추론 파이프라인의 실측 FPS가 아닙니다.
- 임계값·클럭·버퍼 크기는 구현 설정입니다.
- 테스트벤치 파일의 존재는 테스트 통과를 의미하지 않습니다.
- 팬틸트 시제품과 통합 과정은 수행 기록에 있지만, 추적 오차·정착 시간·최대 추적 속도는 정량화되어 있지 않습니다.
- CNN 런타임 가중치 로드와 후처리는 최종 기록에 있으며, 현재 공개 C++ 스냅샷만으로 그 전체 동작을 재현할 수는 없습니다.
- 기록의 약 236 µs는 SNN 연산 지연이며, 20프레임 수집 대기와 구동부 응답을 포함한 전체 지연이 아닙니다.

실기 사진·검출 비교 화면·전류 그래프를 수행 기록에서 가져와 캡션으로 출처와 범위를 표시했습니다. 새로 제작한 도해와 실제 기록 이미지는 구분했습니다. 수치와 계산 조건은 [결과와 측정 조건](results.md), 원인 분석과 검증 과정은 [문제 해결 과정](development.md)을 참고하세요.
